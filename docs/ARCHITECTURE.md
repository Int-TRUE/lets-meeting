# 아키텍처

## 현재 데이터 경로

사용자 요청으로 로컬 실행의 저장 계층을 SQLite로 옮겼다. 브라우저의 `previewService`는 같은 이름의 API 명령을 호출하고, 서버는 기존 도메인 검증을 거쳐 SQLite 트랜잭션에 저장한다. 화면별 더미 데이터를 만들지 않고 중앙 seed와 DB 스냅샷을 사용한다. 사람·회의실 디렉터리도 DB에서 읽는다. IndexedDB는 기존 격리 테스트용으로만 유지한다. Vercel에서는 같은 도메인 검증을 Node Function과 Neon PostgreSQL에 연결한다. 환경별 DB 스키마와 배포 설정은 [배포 운영 지침](DEPLOYMENT.md)을 따른다. 아래 초기 설계/0.2 기록의 로컬 저장소 설명은 당시 구현 이력이다. 자세한 스키마·실행·한계는 [데이터베이스 문서](DATABASE.md)를 따른다.

결정일: 2026-10-20 · D19 중 프런트엔드 기술 스택과 화면 구조만 결정.

## 선택

React + TypeScript + Vite로 작은 SPA를 구성한다. 서버 렌더링이나 공개 검색 노출이 필요하지 않은 사내 회의 도구의 초기 UI이므로 별도 SSR 서버, 전역 상태 라이브러리, UI 프레임워크를 추가하지 않는다. 배포 플랫폼과 내부망 구성은 미정 상태로 유지한다.

| 경계                  | 책임                                                |
| --------------------- | --------------------------------------------------- |
| `src/app`             | 라우팅, 프레임, 데이터 로딩, 전역 스타일            |
| `src/components`      | 화면 간 재사용 UI와 의미 있는 공통 카드             |
| `src/features/home`   | 02/04 홈 및 미리보기 상태 도구                      |
| `src/features/search` | 03 검색, 필터·검색어·스크롤 복원                    |
| `src/domain`          | 모델, 회의 상태, 권한별 조회·검색·집계              |
| `src/data`            | `WorkspaceRepository`와 명시적인 예시 데이터 어댑터 |
| `docs/design`         | 제공된 원본 지침·명세·토큰·보드                     |

홈 데이터는 조회 시 한 번 권한 필터를 통과시키고 카드·일정·검색·회의 수가 같은 결과를 사용한다. 서버 API와 영속 저장소는 이번 단계에 추가하지 않는다. 미리보기 어댑터는 예시 사용자 변경을 지원하지만 실사용 인증을 제공하지 않는다. 실제 서비스 전환 시 서버에서 세션과 Topic 역할, 회의 참가자, 첨부 접근을 검사한 DTO만 내려줘야 한다. 브라우저에 내려간 데이터의 비밀성은 클라이언트 필터로 보장할 수 없다.

## 상태와 시간

화면 로딩은 React 효과의 AbortController로 취소하고 새 조회 중 이전 사용자 데이터를 숨긴다. 단순 UI 상태는 해당 컴포넌트에서 관리한다. 검색어·결과 종류·스크롤은 URL에 보존하여 상세 화면에서 뒤로 돌아와도 복원한다.

상태 계산은 취소 → 명시적 완료 → 종료시각 경과에 따른 요약 필요 → 예정 순이다. 종료시각 경과를 자동 완료로 간주하지 않는다. 화면 날짜는 Asia/Seoul을 명시한다. 예시는 재현 가능한 고정 시각을 사용하고, 서버 시각·저장 정책은 실제 연동 단계에서 결정한다.

## 다음 구현

Topic 생성과 설정 → 3단계 회의 생성 → 예약 어댑터 → 자료·요약 순서로 확장한다. 서버의 인증·권한·중복 예약 검증을 실제 연동과 함께 구현한다. 미정 항목 D01–D18은 자동 확정하지 않는다. 생성·예약·알림 성공을 브라우저 상태 변경으로 표현하지 않는다.

## 브랜드 자산

개별 투명 마스코트와 벡터 로고가 없으므로 최신 승인 보드에서 캐릭터 부분만 CSS로 잘라 장식에 사용한다. 텍스트·카드·컨트롤은 실제 HTML이다. 다른 캐릭터를 생성하거나 화면 전체를 이미지로 대체하지 않는다. 자산을 제공받으면 Brand 컴포넌트 한 곳에서 교체한다. 모바일은 공간 확보를 위해 안내 캐릭터를 생략하며, 브랜드는 메뉴에서 확인할 수 있다.

## 0.2 워크플로 확장 — 2026-10-20

Topic·회의·자료·요약·알림 설정을 `previewService`의 비동기 인터페이스로 연결한다. 데이터 영속화는 IndexedDB의 단일 `readwrite` 트랜잭션으로 묶는다. 권한, 최신 revision, 예약 충돌을 같은 트랜잭션 안에서 재검사하고 회의·예시 예약·알림 이벤트를 함께 커밋한다. 생성 요청 키는 사용자별로 범위를 나눠 중복 생성과 중복 이벤트를 방지한다. 이 구조는 같은 브라우저의 여러 탭에서 경합을 재현하지만, 서로 다른 브라우저의 실제 예약을 조정하는 서버 역할은 하지 않는다.

파일 Blob도 IndexedDB에 저장하고 다운로드마다 현재 Topic·회의 권한을 재검사한다. 파일 추가·교체 실패 때 입력을 보존하며, 교체가 성공하기 전 원본을 바꾸지 않는다. 예시 파일은 가짜 다운로드를 제공하지 않는다. 임시 요약은 완료 이벤트를 만들지 않고, 생성자가 명시적으로 완료할 때만 상태를 바꾼다.

`WorkspaceContext`는 조회 결과와 변경 후 갱신만 관리한다. 입력·모달 상태는 기능 컴포넌트가 소유한다. Data Router의 이탈 차단과 `beforeunload`를 사용하고, 생성 초안은 탭별로 보존한다. 예시 사용자 전환 시 이전 사용자의 화면 상태와 비동기 결과가 다음 사용자 화면을 덮어쓰지 않게 한다.

운영 관리자와 Topic 역할은 독립적이다. 운영 화면은 실제 전송되지 않은 예시 이벤트와 회의실 기본 정보를 보여주며 회의 본문 열람권이나 외부 회의실 수정권을 자동 부여하지 않는다. 알림 필수 여부는 사용자 설정 객체와 분리해 이벤트 생성 단계에서 적용한다. 선택 이벤트만 저장된 개인 설정을 참고한다.

생산 빌드에서는 미리보기 변경을 기본 차단한다. 실제 도입 시 `previewService`를 인증된 서버 API로 교체하고, 같은 권한·중복·경합 테스트를 해당 서버와 외부 연동 계약에 적용한다. 2026-10-30 사용자 요청으로 기본 예약 시간을 09:00~23:00으로 확정했다. 기존 30분 단위는 유지하며 화면·서버 예약·연장 검증에서 공통 설정을 사용한다.
