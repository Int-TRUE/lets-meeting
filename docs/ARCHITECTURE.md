# 아키텍처

결정일: 2026-10-20 · D19 중 프런트엔드 기술 스택과 화면 구조만 결정.

## 선택

React + TypeScript + Vite로 작은 SPA를 구성한다. 서버 렌더링이나 공개 검색 노출이 필요하지 않은 사내 회의 도구의 초기 UI이므로 별도 SSR 서버, 전역 상태 라이브러리, UI 프레임워크를 추가하지 않는다. 배포 플랫폼과 내부망 구성은 미정 상태로 유지한다.

| 경계                  | 책임                                                |
| --------------------- | --------------------------------------------------- |
| `src/app`             | 라우팅, 프레임, 데이터 로딩, 전역 스타일            |
| `src/components`      | 화면 간 재사용 UI와 의미 있는 공통 카드             |
| `src/features/home`   | 02/04 홈 및 미리보기 상태 도구                      |
| `src/features/search` | 03 검색, 필터·검색어·스크롤 복원                    |
| `src/domain`          | 모델, 회의 상태, 권한별 조회·검색·집계              |
| `src/data`            | `WorkspaceRepository`와 명시적인 예시 데이터 어댑터 |
| `docs/design`         | 제공된 원본 지침·명세·토큰·보드                     |

홈 데이터는 조회 시 한 번 권한 필터를 통과시키고 카드·일정·검색·회의 수가 같은 결과를 사용한다. 서버 API와 영속 저장소는 이번 단계에 추가하지 않는다. 미리보기 어댑터는 예시 사용자 변경을 지원하지만 실사용 인증을 제공하지 않는다. 실제 서비스 전환 시 서버에서 세션과 Topic 역할, 회의 참가자, 첨부 접근을 검사한 DTO만 내려줘야 한다. 브라우저에 내려간 데이터의 비밀성은 클라이언트 필터로 보장할 수 없다.

## 상태와 시간

화면 로딩은 React 효과의 AbortController로 취소하고 새 조회 중 이전 사용자 데이터를 숨긴다. 단순 UI 상태는 해당 컴포넌트에서 관리한다. 검색어·결과 종류·스크롤은 URL에 보존하여 상세 화면에서 뒤로 돌아와도 복원한다.

상태 계산은 취소 → 명시적 완료 → 종료시각 경과에 따른 요약 필요 → 예정 순이다. 종료시각 경과를 자동 완료로 간주하지 않는다. 화면 날짜는 Asia/Seoul을 명시한다. 예시는 재현 가능한 고정 시각을 사용하고, 서버 시각·저장 정책은 실제 연동 단계에서 결정한다.

## 다음 구현

Topic 생성과 설정 → 3단계 회의 생성 → 예약 어댑터 → 자료·요약 순서로 확장한다. 서버의 인증·권한·중복 예약 검증을 실제 연동과 함께 구현한다. 미정 항목 D01–D18은 자동 확정하지 않는다. 생성·예약·알림 성공을 브라우저 상태 변경으로 표현하지 않는다.

## 브랜드 자산

개별 투명 마스코트와 벡터 로고가 없으므로 최신 승인 보드에서 캐릭터 부분만 CSS로 잘라 장식에 사용한다. 텍스트·카드·컨트롤은 실제 HTML이다. 다른 캐릭터를 생성하거나 화면 전체를 이미지로 대체하지 않는다. 자산을 제공받으면 Brand 컴포넌트 한 곳에서 교체한다. 모바일은 공간 확보를 위해 안내 캐릭터를 생략하며, 브랜드는 메뉴에서 확인할 수 있다.
