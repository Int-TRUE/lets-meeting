# 데모 데이터베이스

## 실행 환경

로컬은 `npm run dev -- --port 4174`의 SQLite(`data/robot-butler.sqlite`), Vercel은 Node Function과 Neon PostgreSQL을 사용한다. 브라우저는 `/api/demo`를 통해 같은 환경의 데이터를 읽고 수정한다. IndexedDB는 `VITE_DATA_MODE=fixture`인 격리 회귀 테스트에서만 사용한다. DB 파일·접속 비밀값은 Git에서 제외한다.

## 초기 데이터와 일회성 초기화

2026-10-22 사용자 요청에 따라 seed 버전 3에서 기존 계정·Topic·멤버십·회의·참가·첨부 BLOB·개인 설정·알림 이력·중복 요청 기록을 초기화한다. 회의실 테이블의 기존 행·수정값은 건드리지 않는다. 완전히 새 DB일 때만 기본 회의실 5개를 넣는다.

새 디렉터리는 테스트 계정 4명과 참가자 선택용 가상 직원 20명이다. 총 24명의 이름·팀·직책을 보관하고, Topic·회의는 0개로 시작한다. 계정 정보는 [테스트 계정 문서](TEST-ACCOUNTS.md)를 따른다. 추가 직원은 참가자 선택에만 쓰며 로그인 사용자가 될 수 없다. 서버의 조회·변경도 `isTestAccount`를 확인한다.

초기화와 버전 기록은 하나의 DB 트랜잭션에서 처리한다. seed 버전이 이미 3이면 건드리지 않으므로 이후 사용자가 만든 Topic·회의·자료·설정은 보존한다. 전체 초기화를 호출하는 공개 API는 제공하지 않는다.

## 데이터·권한

`people`, `rooms`, `topics`/`topic_members`, `meetings`/`meeting_participants`, `attachments`, `preferences`, `delivery_logs`, `requests`를 분리한다. 관계에 외래키를 적용하고 첨부는 SQLite BLOB/PostgreSQL BYTEA로 저장한다. 직원·회의실 목록은 DB에서 읽어 화면과 서버 검증에 함께 사용한다. 역할·revision·중복 요청·예약 충돌을 저장 트랜잭션 안에서 검사한다.

성 한 글자 프로필은 공통 UI로 렌더링한다. 사람 모델의 선택 필드 `avatarUrl`로 이후 사진 표시를 지원할 수 있으나 사진 설정 UI는 이번 범위에 없다. 새 테스트 환경은 실제 Asia/Seoul 현재 시각을 사용한다.

PostgreSQL 환경/Preview 브랜치별 스키마, 환경변수, 배포 확인은 [배포 운영 지침](DEPLOYMENT.md)을 따른다. 로컬과 배포 DB는 자동 복제하지 않는다.

## 검증과 범위

DB 검사는 이전 사례 데이터에서 초기화할 때 회의실 수정값·추가 회의실을 보존하는지, 이전 계정·회의·첨부·설정·이력이 없어지는지, 이후 만든 데이터를 재접속 때 보존하는지 검증한다. 브라우저 검사는 계정 4개 전환, 직원 검색/프로필, 첫 Topic·회의 생성, 다른 참가 계정의 자료 다운로드를 수행한다.

과거 시안/권한 회귀 검사는 명시적인 `reference` 프로필을 별도 테스트 DB/스키마에만 생성한다. 실제 앱에 사례 데이터를 다시 넣지 않는다. 실제 직원 인증·원텔·Mattermost는 미연결이며 더미 계정 데모다.
