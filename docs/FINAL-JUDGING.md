종료된 `교체 준비 점검` 회의에는 부분 요약과 1/3 완료된 작업 목록을 준비한다. `sujin`이 결정 문장을 보완하고 `wooseok`도 참가자로서 저장할 수 있다.

## 서버 적용 범위

`scripts/replace-judging-data.py`는 기존 자체 서버의 `./butler`와 컨테이너 안의 Node/PostgreSQL만 사용한다. Python 3 표준 라이브러리로 실행되며 앱 이미지와 환경설정을 교체하지 않는다.

**사용자 승인 범위:** 모든 토픽·회의·참가 관계·첨부·요약·후속 작업·기존 발송 기록·요청 중복 방지 기록을 교체한다. 계정, 개인 설정, 기존 회의실, DB 메타데이터는 보존한다. 이미 Mattermost에 도착한 메시지는 이 데이터베이스와 별개이며 삭제하지 않는다.

기본 실행은 조회와 계획만 수행한다. `--apply`에서만 앱을 잠시 중지하고 다음 순서로 실행한다.

1. 스키마·현재 자료의 지문을 확인하고, 계획 이후 변경이 있으면 중단한다.
2. 설치 폴더의 형제 위치 `.robot-butler-judging-backups/<시간>/`에 전체 DB를 비공개 권한으로 백업한다. 백업 목록 검사가 실패하면 삭제하지 않는다.
3. DB 잠금과 단일 트랜잭션 안에서 기존 활동 자료를 교체하고 분당 회의실을 추가한다.
4. 계정·설정·기존 회의실·메타데이터 보존, 첨부 바이트, 참조 관계, 삽입 내용을 확인한다.
5. 기존 앱을 시작하고 실제 health·디렉터리 조회와 DB를 다시 검사한다. 실패하면 백업 복구를 시도하고 검증 결과를 명시한다.

예정 회의의 시작·종료·리마인드 처리는 `suppressed:judging-fixture`로 명시적으로 억제한다. 발송 성공 기록은 만들지 않는다. **일정을 수정하거나 새 회의를 만들면 정상 알림이 발생할 수 있다.** 실제 알림 촬영은 수신 대상과 시간을 정한 별도 단계에서 수행한다.

## 실행

두 파일을 같은 폴더에 둔다. 기본 앱 경로는 `/home/mattermost-admin/robot-butler-direct-20261026`, 기본 확인 주소는 `https://kftc-robot-butler.tailba32fb.ts.net:8443`이다. 설치 위치가 다르면 `--app-dir`, 주소가 다르면 `--base-url`을 지정한다.

```bash
# 기본: 읽기 전용 계획. 기준일은 실행 시점의 서울 날짜.
sudo python3 replace-judging-data.py

# 백업 후 사용자 승인 범위 전체 교체.
sudo python3 replace-judging-data.py --apply
```

일자와 검토한 계획을 고정하려면 다음을 사용한다. 입력한 기준일을 바꾸면 계획을 새로 만든다.

```bash
sudo python3 replace-judging-data.py --base-date 2026-10-28 --summary plan.json
sudo python3 replace-judging-data.py --base-date 2026-10-28 --expect-plan plan.json --apply
```

`status: verified`와 백업 경로를 확인한 뒤 브라우저를 새로고침한다. 실패한 결과를 성공으로 간주하지 않는다. SSH 인증이 없는 환경에서는 이 파일을 준비한 것만으로 서버에 반영된 것이 아니다.

## 복구

출력된 실제 백업 폴더를 사용한다. 복구 전 현재 DB도 별도로 백업하므로 교체 이후의 작업을 보존할 수 있다. 복구는 해당 시점의 전체 DB로 돌아가므로 이후 계정·회의실 변경도 함께 되돌아갈 수 있다.

```bash
sudo python3 replace-judging-data.py --rollback /home/mattermost-admin/.robot-butler-judging-backups/<출력된시간>
```

백업·상태 파일에는 비공개 데이터가 포함될 수 있다. Git, 배포 묶음, 대화에 올리지 않는다.
