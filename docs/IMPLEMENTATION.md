## SQLite 사례 데이터·화면별 보완

브랜치 `task/database-and-screen-refinement`. 로컬 SQLite API와 관계형 테이블, 초기화·마이그레이션, 실제 첨부 BLOB을 도입했다. 사용자 제공 IT운영팀·자동이체·전산기기교체 사례와 후속 회의를 추가했다. 당시 주최자 소속·직급을 보존한다. [DB 설명](DATABASE.md).

01 로그인 배경, 02 얼굴 로고와 제목 뒤 확대 캐릭터, 03 필터 색과 결과 메타, 04 구름 양쪽 잘림, 06 제목 강조, 07 참가자·주최자·요약, 09 단계 표시와 미리보기, 12 생성 성공 일러스트·정보 카드, 15 회의 메타, 16 경고·확인 체크박스, 17 장식·수신 채널·방해금지 제거를 반영했다.

단위·SQLite 검사 20개, 기존 브라우저 52개, SQLite API를 쓰는 브라우저 흐름 1개 통과. SQLite 브라우저 검사는 서로 다른 창의 조회·생성·첨부 다운로드를 확인한다. 원본과 같은 치수의 19개 캡처 및 실제 DB 사례 [홈](qa/database-refinement/home.png), [팀 회의](qa/database-refinement/history.png), [자동이체](qa/database-refinement/autopay.png), [알림](qa/database-refinement/notifications.png)을 확인했다.

정확한 폰트와 일부 원본 이미지는 여전히 다르다. Owner 위임·삭제는 기존 준비 중 상태이며 이번 작업에서 활성화하지 않았다. 실제 인증·외부 예약·메시지 발송은 미연결이다. [생성 에셋과 프롬프트](design/GENERATED-ASSETS.md)에 제작 근거를 기록했다.

## 시안 대비 차이와 남은 범위

비교 기준은 `01-brand-and-entry.png` 및 홈 정보 구조 참고 보드다. 카드·문구·카운트는 실제 텍스트와 공통 컴포넌트로 구현했으며 예시 값은 하나의 데이터에서 계산한다.

- 원본 보드의 서비스 내 알림함·가짜 미읽음 수를 제외했다(D14). 벨은 알림 설정으로 연결한다.
- Topic 멤버 수의 공개 범위가 미정이므로 인원수를 임의 표시하지 않는다(D15). 역할과 접근 가능한 회의 수만 표시한다.
- 개별 투명 로고·캐릭터 파일이 없어 최신 승인 보드의 캐릭터 부분만 CSS로 잘라 쓴다(D18). 홈 안내에는 승인된 집사 의상 포즈, 빈 홈에는 태블릿 포즈를 사용한다. 개별 자산 제공 후 교체한다.
- 모바일에서는 안내 캐릭터를 생략하고 메뉴·브랜드·본문 공간을 확보한다. 카드 한 열과 메뉴 서랍은 명세의 반응형 기본안이다(D17).
- 상단 예시 데이터 안내와 하단 미리보기 상태 도구는 개발용이며 출시 전 실제 데이터 어댑터와 함께 정리한다. 예시 시각은 Asia/Seoul 2026-10-20 13:30이다.
- 01 로그인, 05–20 전체 화면, Topic 생성·수정·삭제, 예약·알림·자료·요약 저장은 이번 구현 완료 범위가 아니다. 링크 연결용 읽기 화면을 해당 기능 전체 완료로 간주하지 않는다.
- 실제 서비스 전환에는 서버 권한 검증, SSO, 원텔 예약, Mattermost, 파일 접근 통제와 미정 정책 확정이 필요하다. 가용 슬롯이나 실제 전송 성공을 모의로 표시하지 않는다.

## 2026-10-24 로컬 Mattermost DM

브랜치 `task/mattermost-dm`. 화면 12(생성·변경 결과), 13(상세·취소), 19(운영 발송 이력)에 서버의 실제 발송 상태를 표시한다. 회의와 이벤트 저장 후 DM을 보내며 실패·불확실 결과를 회의 저장과 분리한다. 새로운 화면·색상 체계는 추가하지 않았다. 실제 발송은 로컬에서만 활성화하고 Vercel은 조회·표시만 반영한다.

SQLite 전송기 검사 6개를 포함해 단위/DB 35개 통과(PostgreSQL 3개는 로컬 미설정으로 제외, CI에서 실행). 브라우저 기존 검사 67개 통과 후 변경된 문구를 검사하도록 보완한 workflows 24개와 DB 브라우저 1개 통과. 실제 로컬 UI에서 정수진 계정으로 시연 회의 생성·14시→13시 변경·취소를 수행했고 각 4명, 총 12개 DM의 게시물 ID·봇 발신자·정확한 두 명의 DM 채널 구성원을 API로 확인했다.

참가 제외 안내에는 새로운 일정·상세 링크를 포함하지 않는다. 관리자 이력에 회의 메시지 스냅샷은 노출하지 않는다. 자동 재시도·자료/요약 발송·리마인드는 이번 범위 밖이다.
