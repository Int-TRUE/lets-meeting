# 매터모스트 로컬 DM 시연

2026-10-24 사용자 요청: Mac Docker의 매터모스트에 로봇집사 회의 생성·변경·취소를 참가자별 DM으로 자동 전송한다. 로봇집사도 같은 Mac에서 `npm run dev`로 실행한다.

## 구성

- 로봇집사: http://localhost:5173 / SQLite
- Mattermost: http://localhost:8065 / 전용 PostgreSQL / Docker 볼륨
- 봇은 일반 사용자 권한이다. 회사 계정/SSO 인증을 구현한 것은 아니다.
- `.env.local`의 서버 전용 변수로 활성화한다. `VITE_` 접두사를 사용하지 않는다.
- `MATTERMOST_ENABLED=true`, `MATTERMOST_URL`, `MATTERMOST_BOT_ID`, `MATTERMOST_BOT_TOKEN`, `MATTERMOST_USER_MAP`(직원 ID → Mattermost 사용자 ID JSON), `ROBOT_BUTLER_URL`을 설정한다.
- 토큰·계정 비밀번호·매핑 파일은 Git에서 제외한다. URL은 HTTPS 또는 로컬 HTTP만 허용한다. 외부 응답·인증정보는 발송 이력에 남기지 않는다.
- 시연 참가자 24명은 각각 별도 계정에 연결한다. 정수진은 사용자가 지정한 기존 관리자 계정에 연결하고, 나머지는 로컬 시연 전용 계정을 사용한다. 다른 사람의 알림을 관리자 한 명에게 몰아 보내지 않는다.

## 동작과 실패 처리

회의 변경과 참가자별 이벤트를 같은 DB 트랜잭션으로 저장한다. 커밋 후 대기 이벤트를 선점해 DM을 전송한다. 네트워크 요청 중 DB 잠금을 유지하지 않는다. 생성 요청 키·수정 revision 검증으로 중복 이벤트를 막고, 같은 프로세스의 이벤트 배치를 순서대로 처리한다.

- 생성: 생성자 포함 참가자 전원.
- 변경: 현재 참가자에게 이전/이후 제목·일시·장소. 제외된 참가자에게는 이전 회의 제목과 제외 안내만 제공하며 새 일정·링크를 보내지 않는다.
- 취소: 현재 참가자에게 취소 안내.
- 본문에는 한국 시간과 권한 검사를 거치는 회의 상세 링크를 포함한다. 사용자 입력의 Markdown과 @멘션은 이스케이프한다.
- 회의 저장 성공과 DM 발송 성공을 분리한다. 실패해도 저장된 회의를 되돌리거나 중복 생성하지 않는다.
- 상태: 미연결 / 대기 / 전송 중 / 완료 / 실패 / 결과 확인 필요. 계정 미연결·인증 오류는 실패로, POST 타임아웃·서버 오류 등 전달 여부가 불명확하면 결과 확인 필요로 기록한다.
- 재시도 정책은 아직 미정이다. 자동·수동 재전송을 제공하지 않는다. 재시작 시 대기 건은 전송하고 전송 중이었던 건은 결과 확인 필요로 변경한다. 외부 전송과 DB 기록 사이에 프로세스가 종료되면 정확히 한 번 전송을 보장할 수 없으므로 실제 DM 확인이 필요하다.
- 연동 전의 과거 미전송 이벤트는 소급 발송하지 않는다. 자료·요약·리마인드는 이번 범위에 포함하지 않는다.
- 관리자 이력 API는 메시지 스냅샷을 제외한다. 회의 발송 요약은 해당 회의 열람 권한을 확인한 후 집계만 반환한다.

## 배포 범위

Vercel은 Mac의 `localhost`에 직접 접속하지 않는다. 사용자 요청으로 추가한 중계 모드에서는 Vercel이 회의와 발송 대기를 같은 트랜잭션에 저장하고, Mac이 HTTPS로 가져와 로컬 Mattermost에 전송한다. 외부 공개나 터널은 필요 없다. 공개 테스트 계정 선택은 회사 인증이 아니므로 서버의 수신자 허용 목록과 Mac의 별도 계정 매핑에 있는 시연 계정만 전송한다. 봇 토큰은 Mac에만 둔다.

## 검증

`npm run check`는 실제 DM 없이 격리된 검사다. SQLite 전송기 검사는 생성·수정·취소, 중복 요청, 권한 거부, 미연결 수신자, HTTP 실패, 전송 결과 불확실성, 재시작 복구를 검증한다. 실제 시연은 별도 테스트 Topic과 미래 회의를 만들어 참가자별 DM 및 발송 이력을 확인한다.

## 배포 앱 → 맥 중계 프로그램

### 시연 시작과 종료

1. Mac에서 프로젝트의 `start-mattermost-demo.command`를 더블 클릭한다. Docker Desktop을 열고 기존 Mattermost/PostgreSQL 컨테이너를 시작한 다음 중계기를 실행한다.
2. 터미널의 `로봇집사 중계 시작` 메시지를 확인하고 창을 켜둔다. 중계 중에는 유휴 잠자기를 방지한다. 덮개를 닫거나 강제 잠자기로 전환하면 중계는 중단된다.
3. https://robot-butler.vercel.app 에서 회의를 생성·변경·취소한다. http://localhost:8065 의 `robot-butler` DM에서 확인한다. 정수진은 기존 `inttrue` 계정이다. 발송 결과는 회의 화면의 새로고침으로 확인한다.
4. Ctrl+C로 중계기를 종료한다. 컨테이너도 필요 없으면 Docker Desktop에서 정지한다. 볼륨과 `data/mattermost-relay.sqlite`는 삭제하지 않는다.

터미널로 시작하려면 프로젝트 폴더에서 `npm run mattermost:relay`를 실행한다. 로컬 로봇집사 개발 서버는 필요 없다. Node.js 22.14 이상을 사용한다. 중계기는 이 맥의 127.0.0.1:8066 포트를 잠금 용도로 사용해 중복 실행을 막고, 해당 포트로 요청을 처리하지 않는다.

### 설정

- Vercel의 기존 robot-butler 프로젝트: `MATTERMOST_RELAY_ENABLED=true`, `MATTERMOST_RELAY_TOKEN`(무작위 32바이트의 64자리 hex), `MATTERMOST_RELAY_RECIPIENTS`(허용된 직원 ID를 쉼표로 연결). Production과 Preview의 인증값은 서로 다르게 설정한다. Preview는 해당 작업 브랜치에만 설정한다.
- Mac의 Git 제외 파일 `.env.mattermost-local/relay.env`: 위 토큰과 `MATTERMOST_RELAY_ORIGIN=https://robot-butler.vercel.app`, `MATTERMOST_ENABLED=true`, 기존 봇 ID/토큰·서버 URL·사용자 매핑·`ROBOT_BUTLER_URL`을 설정한다. 파일 권한은 소유자 읽기/쓰기(600)로 제한한다. 중계기는 상세 링크를 중계 대상 origin으로 고정한다.
- 봇 토큰·사용자 매핑·DB 접속 정보는 중계 요청에 포함하지 않는다. 중계 전용 토큰은 브라우저에 전달하지 않는다. `/api/mattermost-relay`의 claim/ack만 전용 토큰으로 접근한다.
- 이 기능을 끄려면 서버의 활성화 변수를 false로 바꾸고 재배포한다. 인증값 교체 시 서버와 Mac 설정을 함께 갱신한다. 일반 다른 Preview에는 중계를 활성화하지 않는다.

### 대기와 복구

- 평상시 약 5초마다 확인하고, 대기 작업이 있으면 연속으로 처리한다. 네트워크 실패 시 최대 30초 간격으로 재접속한다.
- Mac·Docker가 꺼져 있으면 아직 가져가지 않은 알림은 서버에 대기한다. 재실행 시 순서대로 처리한다. 미연결 상태로 기록된 과거 알림은 소급 발송하지 않는다.
- 서버 DB 잠금으로 한 번에 한 작업만 선점한다. 여러 중계기가 실행돼도 동일 작업을 동시에 가져가지 않는다. 선점 응답을 잃으면 같은 요청 ID로 복구한다.
- Mac의 SQLite 기록에 발송 시도 전 상태와 발송 후 결과를 저장한다. 결과 보고가 실패하면 결과만 다시 올리며 DM은 재전송하지 않는다.
- DM 전송 중 종료·타임아웃처럼 실제 도착 여부를 확정할 수 없으면 `결과 확인 필요`로 기록한다. 2분간 결과가 없는 선점은 다음 조회 때 같은 상태로 전환한다. 자동 재전송하지 않으므로 실제 DM 확인이 필요하다. 이는 외부 전송과 DB 기록 사이의 장애로 인한 중복을 피하기 위한 처리다.
- 생성·변경·취소만 지원한다. 자료·요약·리마인드와 실패 DM의 수동 재전송은 기존 미정 정책을 유지한다.
