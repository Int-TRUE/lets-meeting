# 빈 환경에서 회의 테스트하기

사용자 요청(2026-10-22)에 따라 이전 계정·Topic·회의·자료·설정·알림 이력·중복 요청 기록을 지우고 아래 직원 목록으로 교체한다. 기존 회의실 행과 수정값은 보존한다.

## 진입과 계정

[로그인 화면](https://kftc-robot-butler.tailba32fb.ts.net:8443/login)에서 테스트 계정을 선택한 뒤 홈으로 들어간다. 미선택 상태의 앱 진입도 로그인 화면으로 이동한다. 선택 후 **Topic 만들기 → 회의 만들기 → 장소·시간 → 참가자·자료** 순으로 진행한다. 우측 프로필의 **테스트 계정 변경**으로 로그인 화면에 돌아가 계정을 바꿀 수 있다. 홈에는 계정 선택 영역을 표시하지 않는다. 선택은 탭의 sessionStorage에 보존된다.

| 이름   | 팀           | 직책 | 용도                                  |
| ------ | ------------ | ---- | ------------------------------------- |
| 태평양 | 시스템관리팀 | 차장 | 일반 테스트 + 서비스 운영 관리자 화면 |
| 정금결 | 정보개발팀   | 대리 | 일반 테스트                           |
| 장금별 | DevOps기술팀 | 계장 | 일반 테스트                           |
| 김금달 | CMS개발팀    | 계장 | 일반 테스트                           |
| 테스터 | 테스트       | —    | 일반 테스트 · Mattermost `@tester` 연결 |

서비스 운영 관리자 권한과 Topic 권한은 별개다. 모든 계정은 자신의 Topic을 만들 수 있으며, Topic 생성자가 Owner가 된다. 직급 때문에 다른 Topic의 권한이 자동으로 부여되지 않는다.

## 직원·프로필

위 5명과 별도로 가상의 직원 20명을 넣어 총 25명이다. 이름·팀·직책으로 참가자/회의 관리자를 검색하고 선택한다. 추가 직원은 로그인 계정이 아니며 서버도 이들의 계정 전환 요청을 거절한다. 직원 목록은 실제 DB에서 읽는다.

공통 프로필은 성 한 글자와 고정된 배경색을 사용한다. 헤더·계정 카드·선택 목록·참가자 그룹에 같은 표시를 쓴다. 모델의 `avatarUrl`이 설정되면 사진을 표시할 수 있도록 준비했으며, 사진 변경 화면은 아직 추가하지 않았다.

## 초기화와 보존

seed 버전 3은 이전 버전 DB에 **한 번만** 적용하는 트랜잭션 마이그레이션이다. 이후 만든 데이터는 재시작·재접속·재배포 때 지우지 않는다. 기존 사용자의 유효하지 않은 세션은 오류 화면 대신 계정 선택 화면으로 안내한다. 로컬 SQLite와 배포 PostgreSQL 모두 같은 초기화 규칙을 쓴다. 회의 시각은 새 테스트 환경에서 실제 Asia/Seoul 현재 시각을 사용한다.

기존 디자인 회귀 검사용 사례는 격리 테스트의 `reference` 프로필에서만 생성한다. 실행 중인 앱과 운영 DB에 사례를 다시 넣지 않는다. 테스트 중 생성한 회의는 Preview/테스트 전용 DB에서만 검증하며 사용자에게 제공하는 정식 DB는 빈 상태로 둔다.

## 2026-10-28 시연 표시명 변경

앱 내부 ID와 Mattermost 사용자 ID 매핑은 유지한다. 기존 seed 버전 3 DB는 초기화하지 않고 다음 앱 시작 시 테스트 계정 4명의 people.name만 갱신한다. 회의·토픽·참가·권한·첨부·설정·발송 기록을 보존하며 기존 메시지나 자유 입력 본문은 일괄 수정하지 않는다. 과거 캡처·영상·배포 묶음에는 이전 표시명이 있을 수 있으므로 시연 화면은 새로 캡처한다.

Mattermost 목표 사용자명은 정금결 `@jeong`, 김금달 `@kim`, 태평양 `@tae`, 장금별 `@jang`이다. 저장소 수정만으로 실제 Mattermost 프로필은 변경되지 않는다. 2026-10-28 자체 서버 SSH·앱·Mattermost에 연결하지 못해 실제 계정·충돌·관리 권한·연동 결과는 확인하지 못했다. 서버 반영과 계정 변경 완료로 간주하지 않는다.


## 2026-10-30 테스터 추가

앱 ID `tester`, 표시명 `테스터`를 일반 로그인 계정으로 추가한다. 기존 seed 버전은 유지하며, 재시작 시 누락된 계정만 삽입한다. 기존 사람의 ID·권한과 활동 데이터는 보존한다. 테스터에게 기존 토픽이나 관리자 권한을 부여하지 않는다.

Mattermost에 이미 존재하는 활성 일반 사용자 `@tester`를 봇의 읽기 권한으로 조회한 뒤 반환된 실제 user ID를 `MATTERMOST_USER_MAP.tester`에 저장한다. 계정을 새로 만들거나 비밀번호·프로필·팀·채널을 변경하지 않는다. 사용자 ID 충돌이나 기존 다른 매핑이 있으면 중단한다. 토큰은 기존 서버 환경에서만 읽고 출력하지 않는다.

서버에서 앱 업데이트 전에 읽기 검사, 업데이트 후 연결을 실행한다:

```bash
sudo python3 scripts/link-tester-account.py
sudo python3 scripts/link-tester-account.py --apply
```

기본 설치 경로가 다르면 `--app-dir`을 지정한다. 읽기 검사에는 `--apply`가 없다. 적용 시 설정을 비공개 `backup/tester-link-.../settings`에 보관하고 앱만 재시작한다. 앱에 테스터가 표시되고 실제 실행 중인 연결이 조회한 ID와 같은지 검증한다. 실패하면 이전 연결 설정과 앱 실행을 복구하며 테스터 앱 계정은 남긴다. `TESTER LINK VERIFIED` 전에는 연동 완료로 보고하지 않는다. 검사 과정에서 메시지는 보내지 않는다.
