# 동작·권한 기준

## 권한

Topic 역할과 서비스 운영 관리자는 별개다. UI 숨김만으로 권한을 구현하지 말고 서버 조회·변경·첨부 접근에도 적용한다.

| 작업 | Owner | Master | Attendee |
| --- | --- | --- | --- |
| Topic 수정·삭제·초대·Owner 위임 | 가능 | 불가 | 불가 |
| Topic 내 회의 조회 | 전체 | 전체 | 본인이 참가한 회의만 |
| 회의 생성 | 가능 | 가능 | 불가 |
| 회의 수정·삭제/취소 | 전체 | 자신이 만든 회의 | 불가 |
| 요약 작성·수정 | 해당 회의 참가자 또는 생성자 | 해당 회의 참가자 또는 생성자 | 해당 회의 참가자 |
| 회의 완료 | 해당 회의 생성자일 때 | 해당 회의 생성자일 때 | 불가 |

- 2026-10-24 사용자 지시: 종료된 회의의 참가자 모두 요약 작성·수정 가능. 완료 후 수정도 완료 상태를 유지한다. 생성자의 완료 권한은 유지하며, Topic 관리 권한만으로 비참가자에게 요약 편집 권한을 부여하지 않는다.
- Owner 위임 대상은 기존 회의 관리자 중 한 명이다. 위임 후 이전 Owner 처리와 유일 Owner 보장은 확정 후 구현한다.
- 개별 회의에 초대된 비관리자는 Attendee다. 직급·회의 주최 여부만으로 Topic Owner를 부여하지 않는다.
- 참가자의 Topic 화면은 접근 가능한 회의만 표시한다. 검색 결과, 카드 수, 자료 탭, 멤버 정보에서도 숨겨진 회의·참가자가 누출되지 않게 한다. Topic 수준 멤버 노출 범위는 미정이다.
- 운영 관리자만 알림 발송 이력과 회의실 관리에 접근한다. 운영 관리자에게 모든 회의 내용 열람권이 자동으로 생기는 것은 아니다.

## 회의 상태

| 상태 | 표시 조건 | 주된 화면 |
| --- | --- | --- |
| 예정 | 취소·완료되지 않았고 아직 종료 전 | 파란 배지, 회의 정보·자료·회의실 가는 길 |
| 요약 작성 필요 | 회의 종료 후 아직 완료 처리되지 않음 | 주황 배지, 참가자 요약 작성 유도 |
| 완료 | 생성자가 명시적으로 요약 저장 및 완료 실행 | 회색 배지, 요약 표시, 길찾기 제외 |
| 취소 | 권한 있는 사용자가 취소 확정 | 취소 안내, 예약 해제 및 참가자 알림 처리 |

‘진행 중’을 별도 상태로 표시할지는 미정이며 기본안에서는 종료 전 예정 그룹 안에 둔다. 완료 조건에 시간이 지난 사실만 사용하지 않는다. 시간 판정은 우선 Asia/Seoul을 화면 기준으로 한다. 서버 저장 시각·타임존 정책은 개발 시 결정한다.

### 기본 흐름

Topic 생성/선택 → 기본 정보 → 장소·시간 → 참가자 선택 → 자료·알람 설정 → 회의 생성 → 상세 → 자료 등록/변경 → 회의 종료 → 요약 작성 → 명시적 완료.

예약·알림 실패는 회의 상태와 별도로 나타낸다. 전송 실패 때문에 이미 성공한 예약이나 회의 생성이 성공했다고 중복 표시되거나 다시 생성되지 않도록 한다.

## 자료 상태

- `등록 예정`: 파일이 없고 ‘자료 없음’을 선택하지 않은 상태. 나중에 등록 가능.
- `자료 없음`: 사용자가 자료가 필요 없다고 명시한 상태. 미등록 리마인드 대상에서 제외.
- `자료 등록됨`: 실제 파일 등록 성공 후 표시. 파일 개수·명칭·수정시각은 서버 결과 사용.
- 마지막 파일 삭제 후 상태는 미정이므로 자동으로 ‘자료 없음’으로 바꾸지 않는다.
- 자료 등록/수정은 참가자 알림 이벤트다. 추가·교체·삭제 권한, 파일 허용 형식과 용량은 확정 필요.

## 회의실 예약

1. 명동/분당 선택 → 회의실 → 날짜 → 가능한 시간 범위 선택.
2. 시안은 30분 단위 가정이다. 실제 정책은 확정 후 설정 가능하게 적용한다.
3. 회의 생성 직전과 변경 시점에 서버에서 중복 여부를 다시 확인한다. 화면에서 가능한 슬롯이 최종 예약을 보장하지 않는다.
4. 충돌이면 입력을 보존하고 가용 슬롯을 갱신한 뒤 다른 시간을 선택하게 한다.
5. 예약 실패 상태에서 ‘예약 완료’라고 표시하지 않는다. 회의 생성·예약의 일관성과 실패 복구 방식은 연동 설계에서 확정한다.
6. 일시·장소 변경은 새 예약 확보와 이전 예약 해제가 일관되게 처리되어야 한다. 취소·삭제 시 예약 해제와 알림을 수행한다.
7. 원텔 연동·추가 회의실 등록 방식과 승인 정책은 미정이다. 로컬 예제 데이터를 실제 연동 결과로 표시하지 않는다.

## 알림

기본 채널은 Mattermost 봇의 개인 DM이다. 카카오톡 다중 채널 지원과 메일은 미정이다.

| 이벤트 | 수신 대상 | 설정 |
| --- | --- | --- |
| 회의 생성·초대 | 참가자 | 필수, 끌 수 없음 |
| 일시·장소 변경 | 참가자 | 필수, 변경 전→후 명시 |
| 참가자 추가·제외 | 해당 인원 | 초대/변경 핵심 안내로 취급 |
| 회의 취소·삭제 | 참가자 | 필수, 예약 해제 안내 |
| 자료 등록·수정 | 참가자 | 선택 가능 |
| 회의 전 리마인드 | 참가자 | 시점 선택 |
| 자료 미등록 | 회의 생성자 | D-1에 등록 예정일 때 |
| 요약 등록·완료 | 참가자 | 선택 가능 |
| 요약 미작성 | 회의 생성자 | 회의 후 N일 경과·미완료, N 미정 |

- 리마인드 선택지: 전일 17시, 1시간 전, 30분 전, 10분 전. 기본 전일 17시 + 30분 전.
- 자료·요약 관련 리마인드의 해제 가능 여부와 발송 중복 제거 정책은 확정 필요.
- 방해금지는 현재 명세에서 추후 개발이다. 지원 전 작동하는 스위치처럼 노출하지 않는다.
- 모든 발송의 대상·이벤트·채널·성공 여부·시각을 기록한다. 실패 재시도와 최종 실패의 관리자 조회가 필요하다. 재시도 횟수·간격은 미정이다.
- 발송 로그와 봇 토큰·인증 정보는 구분한다. UI에 비밀 정보를 노출하지 않는다.

## 검색과 탐색

- 권한 있는 Topic과 회의를 구분하여 검색한다. 검색 대상은 원 명세의 제목·설명·관리자 및 회의명·내용·일시·장소·참가자·자료다.
- ‘자료’의 파일명과 파일 본문 중 어디까지 검색하는지는 미정이다. 첨부 본문 인덱싱을 임의로 약속하지 않는다.
- 결과에서 일치 부분을 강조한다. 강조 태그를 만들 때 사용자 입력을 안전하게 처리한다.
- 상세를 본 뒤 돌아오면 검색어·필터·결과 위치를 복원한다.
- 권한 없는 직접 URL에는 존재 여부나 내용을 불필요하게 노출하지 않는다.

## 삭제·취소·위임

대상·영향을 명시한 확인창을 제공한다. 취소와 영구 삭제는 같은 행동으로 취급하지 않는다. Topic 삭제의 하위 자료 보존, 완료 취소/재개, 초대 정보 보존, Owner 위임 이후 역할은 미정이다. 화면 이미지에 쓰인 “보관됩니다/복구할 수 없습니다”만을 근거로 보존 정책을 구현하지 않는다.

### 2026-10-24 참가자·회의실 일정 보완

회의 생성과 수정의 참가자는 해당 Topic 구성원으로 제한한다. 회의실 달력에서는 사용자가 승인한 범위인 모든 회의의 제목·시간·주최자만 별도 조회한다. 회의 상세·파일·검색의 기존 권한은 유지한다.

### 2026-10-24 지각 확인·연장 알림

사용자 요청에 따라 회의 시작 시 생성자에게 참석 확인을 보내고, 선택한 참가자에게 지각 안내와 세 가지 응답 선택지를 제공한다. 참가자는 알림당 한 번 응답하며 생성자가 회신을 받는다. 종료 5분 전 생성자에게 가능한 30분·60분 연장과 변경 페이지 링크를 제공한다. 연장 시 예약 충돌·운영시간을 서버에서 다시 확인하고 참가자에게 변경을 알린다. 생성·변경·취소·지각 메시지에는 승인 마스코트의 가로 배너를 사용하고 일반 리마인드·연장 안내에는 이미지를 넣지 않는다.

### 2026-10-25 사용자 요청 — 회의 편의 기능

- 사용자별 자주 사용하는 회의실을 서버에 저장하며 회의실 메뉴와 생성·수정 화면에서 지정/해제한다. 회의실 메뉴와 생성·수정 화면에서 현재 센터의 즐겨찾기 회의실을 목록 상단에 정렬하며, 별도 즐겨찾기 필터는 두지 않는다. 목록 오른쪽 별표와 정보 제목 오른쪽 버튼으로 지정·해제한다. 정렬이 바뀌어도 선택한 회의실은 유지한다.
- 회의별 자동 리마인드는 기본 꺼짐, 켜면 30분 전을 선택하고 30·10·5·3분 전을 복수 선택할 수 있다. 기존 개인 알림 설정의 이전 선택지와 별도로 회의 설정이 발송 시점을 결정한다. 기존 회의는 소급 활성화하지 않는다.
- Mac 중계기가 연결된 동안 선택 시점별 참가자 DM을 한 번 발송한다. 발송 창은 각 시점부터 1분이며, 오프라인 동안 지난 시점은 몰아서 발송하지 않는다. 변경·취소·종료·설정 해제된 대기는 발송 전에 무효화한다.
- 수동 리마인드는 예정·진행 중인 회의 주최자만 요청할 수 있다. 서버 권한 검사, 요청 중복 제거, 1분 재요청 제한을 적용한다. 발송 현황과 버튼은 상세 화면 맨 아래에 둔다.
- 요약의 후속 작업은 ID·내용·완료 체크 상태를 저장한다. 기존 문장은 줄 단위 미완료 작업으로 표시하며 편집 저장 시 전환한다. 종료된 회의 참가자의 요약 편집 권한과 revision 충돌 검사를 동일하게 적용한다. 상세 요약의 체크 변경은 즉시 저장한다.
- 초대 배너 문구는 “회의에 초대되었어요”, 일반 리마인드에는 시계를 든 집사 배너를 사용한다. 메시지는 `[회의 초대] Topic > 회의`와 일시·장소·주최·참가자·자료·상세 링크를 제공한다. 변경 알림의 전/후 정보와 참가 제외 시 상세 숨김은 유지한다.


## 2026-10-25 회의 생성·자료·회의실 정보 보완

- 사용자 표기는 Topic 대신 **토픽**으로 통일한다. 내부 API·경로명은 유지한다.
- 참가자·관리자 선택은 검색 전 목록을 표시하지 않는다. 시작 시 로그인용 테스트 계정만 조회하고, 직원 검색 API는 이름·팀·직책으로 최대 20명과 추가 결과 여부를 반환한다. 회의 참가자는 해당 토픽 구성원으로 제한한다. 선택한 사람은 칩으로 유지한다.
- 자동 리마인드는 스위치와 선택 카드 UI를 사용한다. 하루 전(24시간)·1시간·30분·10분·5분·3분 전을 복수 선택하며 마지막 선택 해제 시 꺼진다. 서버 검증과 기존 발송·중복 방지 정책에 동일 적용한다.
- 시간 선택 숫자는 20px, 상태는 14px로 표시한다.
- 자료 목록은 교체 대신 삭제를 제공한다. 생성자 권한과 revision을 검사하고 확인 후 삭제한다. 마지막 파일 삭제 시 자료 상태는 등록 예정이며 자동으로 자료 없음으로 바꾸지 않는다.
- 회의실 정보는 대표사진과 가는 법 두 영역으로 나눈다. 등록된 사진·안내도는 모달로 확대하며 Escape·닫기·포커스 복귀를 지원한다. 실제 사진 미제공에 따라 대표사진은 미등록 안내를 사용한다. 사진 URL 연결 후 동일 영역에서 표시한다.
- 검증: 검색 전 빈 상태·250명 검색 결과 제한·토픽 범위, 자료 삭제 권한·충돌·다운로드 차단, 24시간/1시간 알림 발송 시점·중복 방지, 반응형 선택 UI와 확대 모달을 확인한다.


## 2026-10-25 — 회의 참가자 선택·단계 이동 보완

- 회의 생성·수정의 참가자 선택은 해당 토픽 구성원 전체를 처음부터 표시한다. 전체 추가는 검색어와 관계없이 모든 구성원을 중복 없이 선택하며 주최자는 선택을 유지한다.
- 토픽 생성의 직원 검색은 검색어 입력 후 최대 20명 표시 정책을 유지한다. 검색 안내·빈 결과는 카드 전체 너비에 가운데 정렬한다.
- 장소·시간 단계의 취소·이전·다음 및 오류 안내는 시간 선택 요약 바로 아래에 표시한다.
