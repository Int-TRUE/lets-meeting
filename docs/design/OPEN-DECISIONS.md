# 미정 사항과 범위

디자인 확정은 아래 연동·업무 정책의 확정을 의미하지 않는다. 현재 문서만으로 생산 환경의 인증·알림·예약을 실제로 연결하지 않는다.

| ID | 결정할 사항 | 확정 전 처리 |
| --- | --- | --- |
| D01 | 원텔 SSO 또는 대체 인증, 계정·세션 정책 | 로그인 인터페이스만 분리. 로컬 데모는 명확한 모의 인증 |
| D02 | 직원 정보 포털 API·권한·망 접근 | 테스트 직원 fixture와 실제 데이터를 구분 |

| D04 | 예약 단위 30분/1시간, 영업시간, 연속 예약·최대 길이, 타임존 | 시안 30분은 가정. 정책값 확정 필요 |

## 즉시 진행 가능한 개발

공통 컴포넌트·토큰, 승인된 레이아웃, 권한별 표시 규칙, 모의 데이터 기반 화면과 상태 전환은 진행 가능하다. 모의 성공 상태는 개발 환경에서만 사용하며 실제 외부 연동 성공과 구분한다.

## 변경 기록 원칙

결정이 나면 ID, 결정 날짜, 결정 내용, 영향 화면, 근거를 CHANGELOG와 해당 명세에 반영한다. 구현자가 이미지의 빈 부분을 제품 정책으로 임의 확정하지 않는다. 정책 확정이 필요한 작업을 제외한 독립 작업은 계속 진행한다.
