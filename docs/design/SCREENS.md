# 화면별 개발 명세

v1.0 · 화면 ID는 시안과 개발 작업을 연결하는 식별자다. 아래 URL은 구현을 위한 제안이며 라우터·프레임워크 선택을 강제하지 않는다. 뒤로가기·검색 복원·권한 동작을 유지하면 경로를 조정할 수 있다.

모든 데이터 화면은 loading/error/empty/success 상태를 갖는다. 미정 기능은 [OPEN-DECISIONS.md](OPEN-DECISIONS.md)를 먼저 확인한다.

## 01–04 시작과 탐색

기준 이미지: [01-brand-and-entry.png](assets/01-brand-and-entry.png)

### 01 로그인

- 경로: `/login`. 비로그인 진입 또는 세션 만료 시 표시.
- 왼쪽: 집사 옷을 입은 승인 캐릭터, 로봇집사 이름. 오른쪽: 회사 계정 로그인.
- 행동: 지원되는 인증 방식으로 이동 → 성공 시 원래 목적지 또는 홈. SSO 방식은 아직 미정이므로 실제 로그인 연결을 임의 구성하지 않는다.
- 예외: 인증 실패·세션 만료 문구, 재시도. 외부 인증 오류로 무한 이동 금지.
- 시안의 “SSO 검토 중”은 설계 주석이다. 출시 제품에서 불필요한 개발 설명 대신 이용 가능한 로그인 수단만 보여준다.

### 02 홈

- 경로: `/`. 로그인한 사용자.
- 모여 정보 배치: 왼쪽 임박한 회의 카드, 오른쪽 오늘 일정, 아래 나의 Topic. 스타일·브랜드는 로봇집사.
- 카드: 상태, 회의명, 날짜·시간, 장소, 참가자, 자료 상태, `회의 상세 보기` → 13 또는 16.
- 오늘 일정은 시간순. 요약 대기 안내는 사용자에게 처리 권한이 있는 회의만 집계한다.
- Topic 카드 → 07, `Topic 만들기` → 06. 검색 → 03. 초대된 회의가 없으면 04.
- 로그인 사용자의 접근 가능한 데이터만 표시한다. 카운트·참석자 +N·자료 개수는 같은 데이터를 사용한다.
- 캐릭터 영역과 인사말은 겹치지 않는다. 임박한 회의의 선정 기준은 기본적으로 가장 가까운 미취소·미완료 회의이며 진행 중 회의 노출 우선순위는 정책 확정 대상이다.

### 03 검색 모달

- 진입: 헤더 돋보기. 별도 페이지 대신 오버레이 기본안.
- 입력에 초기 focus. Topic/회의 결과를 색과 명칭으로 구분하고 검색어 일치를 강조한다.
- 결과 선택 → 07/13/16. 뒤로가기 → 같은 검색어·필터·결과 위치.
- 빈 검색어: 입력 안내. 결과 없음: 재검색 안내. 오류: 입력을 유지하고 재시도. 권한 필터를 서버에도 적용한다.
- Escape 또는 닫기로 종료하고 원래 버튼에 focus 복귀. 임의 전역 단축키는 기본 요구에 포함하지 않는다.

### 04 빈 홈

- 경로: 홈의 빈 상태. 새 경로를 만들 필요 없음.
- 승인 캐릭터의 태블릿 포즈, “아직 예정된 회의가 없어요”.
- Topic이 있으면 기존 Topic을 보여주고, Topic도 없으면 생성/둘러보기 안내만 표시한다. 시안의 예시 카드·문구 모순을 복사하지 않는다.
- `Topic 둘러보기` → 05, `Topic 만들기` → 06. 생성 권한 정책에 따라 버튼 표시.

## 05–08 Topic

기준 이미지: [02-topic-and-permissions.png](assets/02-topic-and-permissions.png). 모든 옛 로고·서비스명을 로봇집사로 대체한다.

### 05 Topic 목록

- 경로: `/topics`. 나에게 공개된 Topic 목록.
- 필터: 전체/관리 중/참여 중. 카드: 이름·한줄 설명·역할·허용된 회의수와 관리자 표시.
- 카드 선택 → 07. 생성 → 06. 필터 결과 없음과 실제 Topic 없음 구분.
- 참가자에게 숨긴 회의를 전체 집계에 포함해 간접 노출하지 않는다. 멤버 수·목록 공개 범위는 미정.

### 06 Topic 생성

- 진입: 02/04/05의 생성 버튼, 모달 기본안.
- 필수 데이터: 주제명, 한줄 설명, 회의 관리자 목록. 정확한 빈 값 허용과 최대 길이는 정책 확정 전 임의 제한하지 않는다.
- 직원 검색 → 관리자 선택 → 생성. 생성자는 Owner. 원 명세의 모든 사용자 생성 가능을 기본으로 하되 인증 대상 범위는 미정.
- 성공 → 생성된 07. 실패 → 값 유지. 중복 제출 방지. 닫기 시 입력 유실 확인.
- 이미지의 “최대 5명”은 적용하지 않는다. 프로토타입 직원 목록과 실제 포털 연동을 구분한다.

### 07 Topic 상세·회의 흐름

- 경로: `/topics/:topicId`. 제목·설명·관리자·역할, 시간순 둥근 회의 카드와 화살표.
- Owner/Master는 전체 회의, Attendee는 본인 참여 회의만 본다. 과거 회의 요약 접근도 동일하게 제한.
- `회의 만들기` → 09 (Owner/Master). 카드 → 해당 상태의 13/15/16. Topic 설정 → 08 (Owner).
- 완료=회색, 요약 필요=주황, 예정=파랑. 시간순은 날짜·시작 시각 기준.
- 회의가 많으면 가로 스크롤에 명확한 조작 수단을 제공하거나 작은 화면에서 세로 흐름으로 전환. 보이지 않는 노드를 끼워 넣지 않는다.
- “관련 자료/멤버/주제 정보” 탭의 별도 기능 범위는 미정. 시안에 존재한다는 이유만으로 추가 관리 기능을 구현하지 않는다.

### 08 Topic 설정·권한

- 경로: `/topics/:topicId/settings`. Owner만 변경 가능.
- 관리자 목록, 역할 설명, Topic 정보 수정, 초대, Owner 위임, Topic 삭제 진입.
- 위임: 기존 관리자 선택 → 영향 확인 → 서버 저장 성공 후 역할 갱신. 정확한 위임 후 정책은 확정 필요.
- 삭제: 대상과 영향 확인. 실제 보존·하위 예약 처리 정책 확정 전 영구 삭제를 구현하지 않는다.
- Owner 아닌 직접 접근은 거부. 운영 관리자 권한과 혼용하지 않는다.

## 09–12 회의 생성·예약

기준 이미지: [03-meeting-creation.png](assets/03-meeting-creation.png). **입력 3단계 + 결과 1화면**으로 구현한다.

### 09 기본 정보 — 1단계

- 경로: `/topics/:topicId/meetings/new`. Owner/Master.
- 선택 Topic, 회의명, 회의 내용/안건 입력. 안건 편집 UI는 텍스트 또는 목록으로 구현 가능하나 불필요한 독립 업무관리 기능을 만들지 않는다.
- `다음` → 10, `취소` → Topic. 이전/다음 이동 시 입력 보존.
- 필수 누락·정책 위반은 해당 필드 아래 표시하고 첫 오류로 focus 이동.

### 10 장소·시간 — 2단계

- 명동/분당 → 회의실 → 일자 → 시간 선택. 회의실 수용 인원·위치·가용성 표시.
- 30분 단위는 시안 가정. 실제 정책 확정 후 고정하거나 설정값으로 관리한다.
- 가능/예약 불가/선택은 색·텍스트·체크로 구분. 선택 요약에 시작·끝·총 시간을 표시.
- `이전` → 09, `다음` → 11. 회의실 변경 시 이전 슬롯을 유효한 것처럼 유지하지 않는다.
- 충돌 예시는 별도 오류 상태. 실제 성공 상태 위에 항상 빨간 경고를 노출하지 않는다. 선택 범위와 충돌 시간은 일치해야 한다.

### 11 참가자·자료 — 3단계

- 해당 Topic 구성원만 검색·선택하며, 참가자 칩/목록에서 제거할 수 있다. 생성·수정 API도 Topic 외 인원을 거부한다. 초안 복원 시 Topic 외 선택은 제외한다.
- 자료: 파일 첨부/등록 예정/자료 없음 중 모순 없는 상태. 나중에 업로드 가능.
- 오른쪽 요약: 회의명, 일시, 장소, 참가자, 자료 상태.
- `이전` → 10, `회의 생성` → 서버에서 권한·시간·참가자·예약 재검증 후 12.
- 자료 용량/형식·참가자 수 등 미정 정책은 이미지 문구로 확정하지 않는다. 업로드 실패 시 파일 오류와 생성 가능 여부를 명시한다.

### 12 생성 완료

- 서버 성공 결과에 근거해 회의 정보와 예약 결과, 알림 처리 상태 표시.
- `회의 상세 보기` → 13, `Topic으로` → 07.
- 회의 생성·예약 성공, 알림 실패는 구분한다. 단순히 브라우저에서 버튼을 눌렀다고 완료 상태로 이동하지 않는다.
- 새로고침/뒤로가기/재클릭으로 중복 생성하지 않는다. 연동 방식·복구 트랜잭션은 설계 필요.

## 13–16 회의 진행·마무리

기준 이미지: [04-meeting-lifecycle.png](assets/04-meeting-lifecycle.png).

### 13 예정 회의 상세

- 경로: `/meetings/:meetingId`. Owner/Master 또는 초대된 참가자.
- 제목·상태·일시·장소·생성자·참가자, 회의 정보/자료/요약 영역.
- 예정 회의에 길찾기 영역. 실제 회의실 경로와 정적 대체 이미지가 필요하며 현재 보드의 예시 경로를 실제 안내로 사용하지 않는다.
- 수정/취소는 Owner 또는 해당 회의 생성자인 Master. 버튼 노출과 서버 검증 일치.
- 자료 → 14. 요약 작성은 회의 생성자에게만. 회의 종료 후 상태 규칙 적용.

### 14 자료 관리·회의 변경

- 같은 상세의 자료 탭과 수정 패널/모달.
- 파일명·유형·등록자·수정시각. 열람 권한과 다운로드 권한을 연결하고 자료 URL 직접 접근도 검증.
- 자료 추가/교체 권한은 정책 확정 필요. 확정 전 참가자 전원에게 편집 버튼을 자동 제공하지 않는다.
- 회의 수정은 변경 전→후 일시·장소를 확인. 저장 전 예약 충돌 검사. 성공 후 참가자 알림 이벤트.
- 실패 시 입력과 기존 예약을 보존하는 복구 정책 필요. 수정 중 동시 변경은 최신 상태를 재확인한다.

### 15 회의 후 요약 작성

- 경로: `/meetings/:meetingId/summary`. 해당 회의 생성자.
- 종료 후 미완료 회의에 “요약 작성 필요”. 주요 논의·결정 사항·후속 할 일 입력.
- `임시 저장`은 디자인상 기본 제안이며 저장 범위를 명세화하여 구현한다. 임시 저장만으로 완료·완료 알림을 발생시키지 않는다.
- `요약 저장 및 완료` → 확인 → 저장 성공 → 16 및 요약 알림.
- 빈 요약 완료 허용·최소 작성 기준·완료 후 수정 알림은 미정. 임의로 문자 수를 정하지 않는다.
- 이미지의 할 일 체크는 요약 구조다. 별도 담당자 할당·기한·추적 서비스는 범위 밖이다.

### 16 완료 상세 / 예정 회의 취소 확인

- 완료: 회색 배지, 기존 회의 정보·자료·요약. 회의실 길찾기는 표시하지 않는다.
- 요약 수정 노출은 회의 생성자 기준. 완료 취소·재개와 수정 알림 정책은 확정 필요.
- 취소 확인은 **13의 예정 회의에서 별도로 여는 모달**. 완료 화면에 기본으로 띄우지 않는다.
- 취소 대상·참가자 통지·예약 해제 영향 안내. 취소 성공 후 상태 갱신. 실패는 원인과 재시도 안내.
- 취소와 삭제는 구분하며 보존 문구는 실제 정책과 일치해야 한다.

## 17–20 알림·운영

기준 이미지: [05-notifications-and-admin.png](assets/05-notifications-and-admin.png).

### 17 개인 알림 설정

- 경로: `/settings/notifications`. 본인 설정만 변경.
- Mattermost 기본 채널. 카카오톡·방해금지는 미래 기능으로 숨기거나 비활성+추후 제공 표시. 현재 동작처럼 보이지 않게 한다.
- 회의 생성/변경/취소 알림은 **필수·항상 켜짐**, 잠금 아이콘과 설명. 선택 해제 가능한 스위치를 제공하지 않는다.
- 자료 등록/수정, 요약 완료는 선택 가능. 리마인드 시점은 전일17시/1시간전/30분전/10분전.
- 저장 성공 후 반영. 실패 시 편집값 보존. 서버의 필수 알림 정책을 클라이언트 설정으로 우회할 수 없어야 한다.

### 18 서비스 내 알림함 — 보조 제안

- 경로 제안: `/notifications`. 원 명세의 필수 전달 채널은 Mattermost이며 이 화면은 **선택 범위**다.
- 승인 시에만 이벤트 목록·읽음 여부·상세 링크 구현. 알림 링크에서 다시 현재 권한을 검사한다.
- 알림이 가리키는 회의가 취소·삭제되었거나 접근권한을 잃었으면 안전한 안내 표시.
- 알림함 구현 승인 전 벨 아이콘이 작동하는 것처럼 가짜 미읽음 수를 보여주지 않는다.

### 19 관리자 발송 이력

- 경로: `/admin/notifications`. 운영 관리자.
- 시간/대상/이벤트/채널/성공여부, 필터, 오류 상세와 재시도 이력. 최종 실패가 쉽게 드러나야 한다.
- 자동 재시도 정책은 미정. 수동 재시도 버튼은 권한·중복 방지·감사 기록 범위를 정한 뒤 제공한다.
- 실패 로그가 없을 때 정상 빈 상태. 서버 오류·권한 없음은 별도 표시. 봇 토큰·내부 인증 정보 출력 금지.

### 20 관리자 회의실 관리

- 경로: `/admin/rooms`. 운영 관리자.
- 장소·층·수용 인원·연계 출처·상태. 회의실 정보와 안내 경로 자산 관리.
- 추가/수정/비활성은 원텔 연동 및 승인 정책 확정 후 구현. 외부 동기화 필드를 임의로 편집 가능하게 두지 않는다.
- 이미 예약된 회의실 변경·폐쇄 시 예약 영향 확인. 삭제를 비활성과 같은 것으로 구현하지 않는다.
- API 실패 시 이전 목록을 성공 최신 상태라고 표시하지 않는다.

## 공통 예외 상태 체크

- 필터 결과 없음과 전체 데이터 없음
- 세션 만료, 권한 변경, 초대 제외, 삭제된 회의
- 예약 경합, 파일 실패, 저장 실패, 알림 실패
- 중복 제출, 브라우저 새로고침, 검색에서 상세 후 복귀
- 입력 중 모달 닫기/다른 화면 이동
- 긴 한글 제목, 긴 파일명, 큰 참가자 목록, 빈 요약

보드에 별도 이미지가 없더라도 위 상태를 구현 범위에서 누락하지 않는다. 기능 정책이 미정인 상태는 임의로 선택하지 말고 OPEN-DECISIONS 항목과 연결한다.

## 2026-10-24 회의실 탐색 보완

- `/rooms`, `/admin/rooms`: ‘센터’ 필터, 화살표 오른쪽 16px 여백, 층 숫자 오름차순 목록.
- 회의실 선택 시 월 달력과 날짜별 세로 목록을 함께 표시한다. 날짜에 회의 수를 표시하고, 목록은 시작 시간순으로 회의명·시간·주최자를 제공한다.
- 사용자 추가 지시로 모든 Topic의 예정·진행 중 회의 요약을 공개한다. 본문·참가자·자료·요약은 포함하지 않으며 상세 링크는 기존 열람 권한이 있는 사용자에게만 제공한다.
- 취소·완료·종료 회의 제외. 로딩·오류·재시도·빈 날짜를 구분하며 센터/검색 변경으로 선택 회의실이 제외되면 첫 결과를 표시한다.
